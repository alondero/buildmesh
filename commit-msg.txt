fix(usage): rearchitect PR #1488 against main's #1489 — fix SWR-on-error, wire isRefreshing on mount

Rearchitect of the four round-1/2/3/4/5 commits against the
superseding architecture shipped by main's #1489. Most of PR #1488
was tied to an architecture main moved past on the same day:

  - RightShell, probeRail, UsageInspectorPanel, usageOpenEpoch,
    usageCacheStore, USAGE_DESTINATION, resolveUsageContext, the
    persistent mod-level Usage cache, the warm-cache mount
    revalidation path — all dead under main's #1489, which:
      * removed the Probe rail entirely (title-bar nav replaces it),
      * restored `usage` as a regular ProbeTab (so `probeTab: 'usage'`
        drives the inspector, not `usageOpen`),
      * shipped a `ProbePanel` gatekeeper pattern (1-hook
        subscription, body inside `ProbePanelContent`).
    All of that is now main. None of the #1488 dead code is
    present on `rearch-1488`.

The genuinely-useful fixes that survive the rearchitect:

1. True stale-while-revalidate on refresh error

   Main's `<UsageTab>` still rendered the body as
   `<ErrorState>` on every refresh rejection — the round-3
   review-flagged "I clicked Refresh and lost my view of the
   meters" bug.

   Fix:
   - Keep the prior cached rows on screen when a refresh fails.
   - Surface the error as a non-destructive toolbar alert
     (`role="status"`, "Refresh failed — showing last known data")
     pinned alongside the Refresh button.
   - The body falls back to `<ErrorState>` ONLY when there are no
     prior rows to keep (cold-cache first-load rejection).
   - The pre-existing test that asserted the old broken behavior
     (`renders exactly one error element on a forced-refresh
     rejection after rows have loaded`) is replaced with one
     that asserts the new contract — rows stay visible, alert
     surfaces in the toolbar.

2. Wire isRefreshing during mount-time IPC

   Main's `handleRefresh` flipped `isRefreshing` but the mount
   `useAsyncEffect` didn't, so the warm-cache mount revalidation
   never carried the dim/busy affordance — the same phantom
   60%-opacity claim the round-3 review flagged.

   Fix:
   - `loadMeters(force, { silent? })` now owns the
     `isRefreshing` lifecycle internally (set before the IPC,
     cleared in `finally`).
   - The mount-time `loadMeters(false)` call runs without
     `silent: true`, so `isRefreshing` correctly fires on the
     cold-cache first load too.
   - `handleRefresh` simplifies — it just awaits `loadMeters(true)`
     and lets the internal flag management drive the affordance.
   - This is consistent with the Git Issues / PRs / Archive
     tabs that already flip `isRefreshing` from `loadMeters`.

Note: the warm-cache stale-while-revalidate path itself
(mod-level cache, instant prior-rows render on remount) is
NOT reimplemented here. That was a PR #1488 design choice tied
to the global-surface architecture; main has Usage as a
probe tab with stateful `meters`, so every mount starts cold.
The cold-cache first load still hits `<LoadingState>` until
the IPC settles; the SWR-on-error fix is the user-facing
contract that matters.
