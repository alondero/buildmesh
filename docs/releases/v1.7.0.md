# Buildmesh v1.7.0

<!-- Audience: Buildmesh users. Lifecycle: draft before the matching tag is published; historical release record afterward. -->

_2026-11-06 — 74 commits since v1.6.1 (2026-10-26)_

v1.7.0 is a **feature** release. Custom API providers are configured in one form instead of three, Codex can hold several ChatGPT logins at once, the phone gets a rebuilt navigation and an attention-first home, and you can see what an agent is doing without opening its terminal. Underneath, a long list of smaller annoyances are fixed — from a launch that a routine CLI update used to refuse to an agent whose run was cancelled out from under it.

---

## Highlights

- **Custom APIs are configured in one setup flow.** Setting up a provider used to mean saving a credential, then configuring a provider route separately, then creating a launch configuration — three steps in three places, and the first form only collected a name and a key. Providers now takes the API type, base URL, model and key in one form and saves the account, the provider route and a named launch configuration in one transaction. OpenAI Responses through Codex and Anthropic Messages through Claude Code are both supported, the credentials-only form still works for a provider you configure elsewhere, and the Kimi ID-based protocol rejection is gone.
- **Codex can hold several ChatGPT logins.** Codex keeps one signed-in ChatGPT account per `CODEX_HOME`, so two ChatGPT Pro subscriptions meant picking one. Each additional Codex login is now its own home folder: **Settings › Launch Configurations › Codex logins** adds a named login (Buildmesh creates `~/.codex-accounts/<id>/` and copies `config.toml`/`AGENTS.md` once), signs it in without opening a window, renames it, or removes it. With more than one login the spawn menu gains a login submenu between the Codex row and its launch configurations, the Launch Configuration editor gains a **Login** field, and Usage shows one meter per login labelled with its name and email. The login is frozen on the launch plan, so a resumed session stays on the account you chose.
- **Node Glance shows what an agent is doing without opening its terminal.** A status glyph says which state a node is in, not what it is doing there, so the usual way to find out was to open the terminal — which on the phone is screens deep. A new summary shows the latest tool call (`Now: Bash · npm test` while running, `Last: …` otherwise, plus the two before it and a count since the prompt), the last message the agent wrote, the prompt it is working on, and `Running for 12m · session 2h · last activity 6s ago`. It leads the Android node screen as a **Right now** card, sits on Work details in the browser phone client, and appears as a hover card beside a desktop sidebar row. It is built on the transcript readers each harness already has, so a new harness gets a glance with no extra code.
- **The Android app is rebuilt around destinations and steps.** The bottom bar offered Overview, Work and Capture — but Overview and Work were two halves of one path, so on a tablet they had nothing left to switch, and Capture was an action presented as a place. **Meshes, Usage and Settings** are now the peers (a bottom bar on a phone, a navigation rail from 600dp wide), and a mesh is one step below Meshes, so Back climbs one step. **New task** is a floating button over Meshes and opens Capture for the selected mesh. Overview now lists meshes and Work lists that mesh's agents, matching the desktop layout; the Work tab drops its mesh switcher, search field and status filter. Opening an agent also selects its mesh, so Back lands on the mesh the agent belongs to however you reached it. (#2608)
- **The phone leads with what needs you.** Every agent waiting on a person is pinned above the mesh list on Overview, with what it asked, its mesh and branch, and the one action its request actually supports. The approval buttons send the same `Allow (Y)` / `Deny (N)` and `Approve (Y)` / `Deny (N)` the desktop sends, so the phone answers the harness in the harness's own language. Questions and unclassified requests open the terminal instead of guessing how the harness wants a choice picked. The reply composer sits directly under the request it answers instead of below the PR and Circuit panels, and the dashboard refresh bar no longer pulses on the five-second poll — it belongs to the first load and to a refresh you asked for. (#1966)
- **OpenCode 2 is supported as its own harness.** OpenCode 2 uses the same command as V1, but the V1 adapter cannot read its sessions, deliver attention, or apply V2's changed TUI launch contract, so OpenCode 2 now has a separate version-gated adapter and existing V1 node identities are preserved. OpenCode's native subagent sessions are also tracked as owned work: the attention plugin reports a child's start and end, so a parent that is idle while a subagent still runs reads as background work rather than Ready. (#2655) (#2636)
- **A stale provider pairing warns instead of refusing.** A Codex proxy route's pairing verification is a signature over the harness, provider, endpoint, model, credential, runtime and Codex build — so a routine `codex-cli` update turned the record Stale and the launch was refused with "the Codex CLI changed". Verification is now advisory: an unchecked, stale or previously failed pairing still launches, the user is warned with the reason, the spawn menu row carries the caveat, and a stale route re-checks in the background so the next launch finds a current record. The failures retrying cannot fix — a disabled account, a missing credential, an unresolvable endpoint — still fail closed. (#1198)
- **Two smaller things worth knowing.** **Settings → General → Appearance → Interface text size** scales the interface from 100% to 150% in 5% steps (the smallest type renders at 9.75px today). And a harness that cannot take a prompt on its command line now gets one typed into its terminal once the TUI looks booted, so a Probe issue or PR spawns with its prompt instead of dropping or refusing it.

## What is new

### Providers and setup

- A custom API is now configured in one form: the API type, base URL, model and key go in together, and Buildmesh saves the account, the provider route and a named launch configuration in one transaction. OpenAI Responses through Codex and Anthropic Messages through Claude Code are supported, and the credentials-only form is still there for a provider you configure elsewhere.
- A Codex proxy route whose pairing verification went stale — most often because the Codex CLI auto-updated — now launches with a warning instead of being refused, and re-checks in the background so the next launch finds a current record. (#1198)
- MiniMax M3.1 Flash is accepted in Codex and is the default there, and `MiniMax-M3.1-Flash[1m]` is the default on the Claude surface. Haiku and the small/fast model stay on `MiniMax-M2.7`, because Flash always reasons and that is wasteful for background work such as session naming. Existing saved pairings keep their stored model.
- The Kimi ID-based protocol rejection is gone from provider setup.

### Harnesses and agents

- OpenCode 2 is a harness of its own, version-gated, running alongside OpenCode 1 without changing existing node identities. (#2655)
- OpenCode's native subagent sessions are tracked as owned work, so a parent that is idle while a child session is still running reads as background work rather than Ready. (#2636)
- Codex can hold several ChatGPT logins at once, each its own home folder, with a login submenu in the spawn menu, a **Login** field in the Launch Configuration editor, and one usage meter per login. The login is frozen on the launch plan, so a resumed session stays on the account you chose.
- A harness that cannot take a prompt on its command line now has the prompt typed into its terminal once the TUI looks booted, so a Probe issue or PR spawns with its prompt instead of dropping or refusing it.
- A harness turn that has no hook to signal completion now completes through the harness's result file.

### Mobile and Android

- The native app's navigation is rebuilt around destinations and steps: Meshes, Usage and Settings are the peers, a mesh is one step below Meshes, and **New task** is a floating button over Meshes instead of a bottom-bar slot. (#2608)
- The phone's home surface leads with what needs you: every agent waiting on a person is pinned above the mesh list with the one action its request supports, and the reply composer sits directly under the request it answers. (#1966)
- Overview lists meshes and Work lists that mesh's agents, matching the desktop layout. The Work tab drops its mesh switcher, search field and status filter.
- Agents can be searched within the selected scope. (#2683)
- A new task prompt can be dictated with Android speech input. The transcript is appended to the saved, editable draft before you start the agent.
- A Work row can be swiped to reveal **Close**, which stops and removes that one agent while keeping its worktree and files.
- The spawn split button carries the default provider's mark, and the launch choices and account selection are the same on Android and in the browser phone client. (#2698)
- Pull requests can be listed by open or closed state, and terminal links open in the phone's browser.
- The semantic-turn banner sits above the Android terminal, waiting agents sort first inside each Work mesh group, and every listing screen has one refresh surface. (#2609) (#2613) (#2607)

### Reviews and Circuits

- Each review round is recorded in an append-only ledger, so a verdict cannot be lost between the reviewer and the implementer. `npm run harness -- review --show` prints the previous round's verdict, its outstanding findings and the paths whose content changed since the last reviewed revision. (#2630)
- Closing an agent cancels the runs that were still active under it.
- A transient interruption in a native turn is recovered instead of ending the turn.
- Reviewers are retained after a review round's allowance is exhausted, the final approval evidence is included in merge hand-offs, and a checkpoint is raised only for a blocker a person actually has to clear.
- Circuit input notifications are actionable, and Claude background work ends when its own registry stops listing it.

### Desktop

- **Settings → General → Appearance → Interface text size** scales the interface from 100% to 150% in 5% steps.
- First-run actions and settings are simpler, and the scope labels and the empty-state classifier stay honest.
- A late attach no longer steals Probe focus, and a submitted prompt that goes quiet gets one defensive Enter instead of sitting there.
- The run fingerprint no longer depends on the toolchain probe. (#2581)
- Reviewer launch configurations can be selected, and the headers condense to destination and scope.
- The overview condenses its meshes and prioritises active work.

### Performance and maintenance

- GitHub state is fetched in one compact request instead of several. (#2623)
- A failing pool fill backs off, and missing meshes stop being polled. (#2602)
- The decorative infinite animations pause when the window is not foreground, so the renderer is no longer pinned near one core. (#2599)
- The write-ahead log is bounded and duplicate Circuit observations are collapsed, and bulky run context values move out of `context_json`. (#2600) (#2601)
- Background polling no longer depends on sleep-based intervals. (#2620)
- `libz-sys` is upgraded past RUSTSEC-2026-0418. (#2644)
- The webview user-data folder is isolated per app-data profile, so separate profiles on one Windows machine no longer share WebView2 local storage. (#2469)

## Upgrade notes

- **No action needed.** Every change above is applied by the update; there is no setting to change and nothing to reinstall.
- **The in-app auto-updater offers v1.7.0 to existing Windows and macOS installs as usual.** The Windows installers and the signed Android APK ship as they did in v1.6.1.
- **Existing Codex pairings keep their stored model.** MiniMax now defaults to `MiniMax-M3.1-Flash` on the Codex surface, but only new attaches pick up the new default.
- **Existing saved pairings are no longer blocked by a stale record.** A Codex proxy route whose pairing went stale because the CLI was updated now launches with a warning instead of being refused.
- **macOS is still early access.** The macOS builds remain ad-hoc signed with no Developer ID certificate and no notarization, so Gatekeeper blocks the first launch exactly as SmartScreen does on Windows — right-click the app, choose **Open**, then **Open** again. This release's macOS artifacts were built and audited on native runners, but the installed-app check (browser download, Gatekeeper approval, a real CLI task, session resume and the in-app update flow) was **not** run for this tag: no native Apple Silicon or Intel Mac was available. The `MACOS-INSTALLED-RECEIPT.json` attached to this release records that coverage as unverified.
- **The APK stays out of the updater feed.** `latest.json` carries the Windows and macOS desktop platforms only; the APK keeps its own `.sha256` sidecar.
