# Buildmesh v1.6.0

<!-- Audience: Buildmesh users. Lifecycle: draft before the matching tag is published; historical release record afterward. -->

_2026-10-25 — 53 commits since v1.5.1 (2026-10-19)_

v1.6.0 is a **feature** release. Buildmesh gains a new native harness, a phone that can tell you when an agent needs you, fleet coordination from the command palette, and a title bar that adapts to the window you have. Underneath, a long list of smaller annoyances are fixed — from a mesh row you could not select with the keyboard to a node that failed to spawn without ever saying why.

---

## Highlights

- **Perch is a native harness.** Buildmesh launches the `perch` CLI directly, starts a fresh session with `--thread` and resumes a saved one the same way, and runs unattended with `--permission take_the_wheel`. Sign-in is read from the CLI, an expired access token is refreshed and the rotated refresh token is persisted, and a failed refresh leaves the session file alone. Starter, Pro and unlimited accounts become usage meters; a missing sign-in is reported as "no credential" rather than as an error.
- **Companion works from the command palette.** Press `?` in the Omnibar to hand work to a companion agent that can read your fleet, GitHub and Circuits, and can launch issue- or prompt-backed worktrees and node prompts. The task keeps running after the palette closes, a header pill reopens progress and results, and anything that terminates a session or changes a reviewer asks first. Tasks reserve a spawn budget (5 by default, up to 10), and stale confirmations are rejected.
- **The phone can watch for you.** An opt-in Android foreground service holds the desktop's event feed open, so an agent that asks a question or wants permission reaches the phone while the app is in the background. The notification deep-links to the node and clears itself when the node resolves — including when you answer on the desktop. (#2316)
- **Usage meters on the phone.** Read-only Usage pages in the mobile web and Android apps show your provider usage, backed by the same provider fetchers as the desktop and the last-known cache. Readings survive a refresh error, and pending Capture launches are preserved. (#2576)
- **The title bar adapts to your window.** Below 1440px one labelled **View** selector replaces the row of unlabelled symbols; from 1440px the five labelled view segments and the scope picker return. Below 1700px, Usage, Zoom, Settings and Mobile fold into the **More** panel with their names and descriptions. The grid search field, scope label and shortcut hint now size to the room they have, from 900px to 2560px. (#2421)

## What is new

### Mobile and Android

- The mobile web client renders the desktop's spawn menu on issue cards, open pull request cards and mesh cards as a split button: the main half starts the surface's default launch, the chevron half opens the Spawn Menu so you can pick a different Spawn Option or a saved Launch Configuration. A failed launch is reported inside the open menu sheet, which stays open so you can try again. (#2385)
- The Android app can notify you when an agent needs attention in the background, through a user-enabled foreground service that follows your paired desktop credential. (#2316)
- Read-only Usage pages show provider usage on the phone. (#2576)

### Agents and harnesses

- Perch is a first-class harness with its own usage meter. The meter shows capped windows as percentage bars only, and the monthly allowance reset follows the subscription's billing period when Perch reports one.
- The AI Assistant harness is now selected by the same background-inference capability and launch resolver used for node naming, instead of requiring a native Claude subscription. An AI Assistant Launch Configuration picker was added to Provider defaults.
- MiniMax Code now observes prompt submissions, so starting another prompt clears the previous attention state, and native BYOK references such as `custom_provider:local/MiniMax-M3#variant` are accepted.
- Circuits can copy and attest manual prompt delivery, preserving submission correlation through manual recovery for initial, injected, continuation and wake-up prompts. (#2541)
- The Usage Meter for Freebuff is back: it reads the current daily allowance API with the CLI bearer and shows the same daily percentage and reset as Freebuff's own usage settings, including with no session active. (#2535)

### Reviews and Circuits

- Review setup is no longer hidden behind a node header icon. A compact panel above the Agent Node terminal offers **Add review**, or shows the existing Circuit's status, round, current step and attention state, with **View circuit** opening the full Overview.
- Review rounds can be configured on active runs from Probe and Circuit Overview — one to nine rounds or unlimited — and the allowance applies to review retry loops only, leaving normal approval routing alone.
- The approved merge hand-off now names the rebase onto the pull request's base branch and explicitly authorises the rebase, the conflict resolution and the force-push, resolving every conflict in favour of the approved work. A conflict that would change what the reviewer approved is reported instead of merged.
- Circuit completion is reconciled with the native task registry, so a failed or lost task no longer completes a circuit silently. (#2560)

### Desktop

- The Launch Configuration editor progressively discloses its advanced fields. The endpoint and raw extra arguments live behind one **Advanced options** disclosure that explains when they are needed, opens itself when the configuration already carries an advanced value, and refuses to collapse while a custom model is selected. (#2423)
- A node that fails before its harness launches now says why — including a working tree wrongly flagged as bare — and the reason reaches the desktop toast.
- The Probe's Repository destination stopped rescanning every branch. The per-commit patch-id is memoised for the lifetime of one read, the ancestry question is answered with the merge base the squash scan already needs, the scan is bounded by a wall-clock budget, and a truncated scan reports an unknown merge status rather than "not merged". A repository with hundreds of branches now renders instead of spinning for tens of minutes. (#2580)
- A disconnected drive or an unavailable project folder is explained with its OS cause before Git discovery starts, instead of failing later with a Git diagnostic. (#2504)
- The sidebar mesh row is keyboard-selectable: the mesh name is a real button in the natural Tab order, Enter and Space select the mesh, the active mesh is marked `aria-current`, and closing the context menu returns focus to the name. (#2464)
- An empty workspace shows one mesh-creation call to action, not two stacked in the same column. (#2468)
- A Settings draft is no longer committed behind a discard prompt. Escape, the header × and a backdrop click keep the draft uncommitted and dirty so the prompt can ask about it; an ordinary blur or tab switch still saves as before. (#2458)
- Agent History cards show real times again. Every card used to read "just now" because the stored timestamp was parsed with a stricter format than the database wrote, and the fallback handed the UI the current clock. Cards now show when the session last changed state and when its process started, in UTC.

## Upgrade notes

- **No action needed.** Every change above is applied by the update; there is no setting to change and nothing to reinstall.
- **The in-app auto-updater offers v1.6.0 to existing Windows and macOS installs as usual.** The Windows installers and the signed Android APK ship as they did in v1.5.1.
- **macOS is still early access.** The macOS builds remain ad-hoc signed with no Developer ID certificate and no notarization, so Gatekeeper blocks the first launch exactly as SmartScreen does on Windows — right-click the app, choose **Open**, then **Open** again. This release's macOS artifacts were built and audited on native runners, but the installed-app check (browser download, Gatekeeper approval, a real CLI task, session resume and the in-app update flow) was **not** run for this tag: no native Apple Silicon or Intel Mac was available. The `MACOS-INSTALLED-RECEIPT.json` attached to this release records that coverage as unverified.
- **The APK stays out of the updater feed.** `latest.json` carries the Windows and macOS desktop platforms only; the APK keeps its own `.sha256` sidecar.
- **A saturated database reader pool no longer takes the app down with it.** The pool now returns a retryable error that the HTTP boundary answers with 503, and a circuit worker treats an unavailable read as unknown instead of cancelling the run. If you see a transient "try again" message under heavy load, that is the new, recoverable behaviour. (#1533)
- **Windows and WSL checkouts keep their scoped Git trust.** Linked worktrees on WSL now derive their trust from an already trusted source instead of losing it on restart or after a move. (#2509)
