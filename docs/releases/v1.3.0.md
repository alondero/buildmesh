# Buildmesh v1.3.0

<!-- Audience: Buildmesh users. Lifecycle: draft before the matching tag is published; historical release record afterward. -->

## Issues and Pull Requests panels

- The Issues and Pull Requests panels now have a filter box in their toolbar.
  Typing narrows the list as you type — issues match on title, description, and
  labels; pull requests match on title, description, and branch name.
- Each row now shows quiet badges under its title: issue labels (the first few,
  with a "+N more" chip when there are more), the branch a pull request is
  built from, the fork it came from (when it differs from your repository), and
  a Draft marker. The "Blocked by #N" warning now appears as a badge with a
  coloured stripe along the row's edge instead of small text under the buttons.
- Opening an issue or pull request now shows its full text in a bordered panel
  instead of loose text, and rows without a description no longer show an
  expand arrow.

## Documentation

- Added a documentation hub, task-oriented user guide, troubleshooting guide,
  developer guide, and documentation quality gate.

## Windows terminal cursor

- Fixed the text caret jumping around during animated Codex redraws, including
  Astra's composer glitter. Buildmesh now bundles a matching Microsoft ConPTY
  runtime pair that preserves synchronized frame ordering. Animations remain
  enabled; restart Buildmesh after upgrading to use the new runtime.

## Window controls (Windows)

- The minimise, maximise/restore, and close buttons in the title bar now behave
  like the ones in other Windows 11 apps. Hovering **Maximise** opens the
  system's snap layouts, the buttons use the standard Windows backplate on hover
  and while pressed, and the caption icons dim when the window is not focused.
  The title bar itself is unchanged.

## Window controls (macOS)

- The red, yellow, and green window buttons in the title bar now behave like the
  ones in other Mac apps. Hovering anywhere over the three reveals all three
  symbols at once, each button darkens while it is held, and the whole set turns
  grey when the window is not focused — going back to its colour as the pointer
  reaches it, so you can see what you are about to click. The buttons are drawn
  at the standard macOS size now. The title bar itself is unchanged; the green
  button still maximises rather than entering full screen.

## Command Code typing

- Typing into a Command Code node works again. Command Code 1.56 and later
  can ignore keys on Windows when a paste or a startup keyboard probe leaves
  the prompt stuck. New nodes skip that probe, do not wrap those pastes in a
  way that locks the prompt, and still show the TUI in colour. See
  Troubleshooting if an older node is still stuck.

## Muse on Windows

- Meta Muse now appears in the Spawn Menu on Windows when `muse.exe` is on
  PATH. When both a native Windows install and a Muse install in the default
  WSL distribution are present, the Windows-native entry is used and the WSL
  one is hidden; only the WSL entry is shown when no native install is
  detected.
- On Windows checkouts where Git stored the `AGENTS.md` / `.agents/skills`
  links as plain pointer files, launching Muse — natively or through WSL —
  now restores those links first instead of failing while starting.
- Git and GitHub CLI commands inside a Muse node authenticate again. Muse
  runs its sessions inside its own OS sandbox, which blocked access to the
  system credential store that `gh` and git use for GitHub sign-in on
  Windows, so pushes, fetches, and `gh` calls failed with 401 while other
  agents on the same machine worked. Buildmesh now starts Muse with its
  sandbox disabled, matching every other agent.

## Usage meters

- A provider you are not currently signed into no longer loses its usage meter.
  Antigravity, Grok, and Meta Muse only report usage while their CLI login is
  fresh, so their rows used to vanish on a fresh start — before you had signed in
  that day. Buildmesh now remembers the last reading each provider reported for
  up to seven days and shows it, marked **Last known value · N days ago**, so a
  stale figure is never mistaken for a live one. With nothing remembered, the
  meter stays hidden as before. Live rate-limit and connection errors, and a
  rejected API key, are unchanged.

## Cline

- Cline is now a supported harness. When `cline` is installed (the npm
  install on Windows, or `cline` on PATH on macOS/Linux), a **Cline** row
  appears in the Spawn Menu and can be launched, resumed with
  `cline -i --id <id>`, and given a model, reasoning effort
  (`none|low|medium|high|xhigh`), and prefill prompt from Spawn
  Configurations.
- Cline is a **Native Provider** — it authenticates through its own
  `cline auth` flow. Buildmesh never writes Cline's configuration. When you
  attach one of your Model Provider accounts, Buildmesh injects that
  account's API key into the Cline process at spawn (an Anthropic- or
  OpenAI-surface provider account works without reconfiguring it for Cline).
- WSL is not a supported runtime for Cline in this release.

## Agent spawn lifecycle

- The **Start review or circuit** button on an Agent Node now follows the
  same liveness check the backend already uses (`PROCESS_REGISTRY.is_alive`)
  instead of the node's `pending`/`spawning` status alone. A node whose PTY
  reader is actually registered but whose DB row is still transient — or
  stranded on "Starting…" by an upstream swallow — lights up as eligible
  immediately, so you can kick off a review without waiting for the status
  badge to flip.
- A class of node-spawn failures that used to leave an Agent Node stuck on
  "Starting…" until app restart — every `SpawnOutcome::Skipped` short
  circuit, `SpawnOutcome::AlreadyActive`, and any panic that escaped the
  spawn future — now flow through the session lifecycle and emit a terminal
  `node-spawn-failed` (or `node-spawn-completed`) event. The badge updates
  to **Error** (or **Running**) instead of lying indefinitely.
