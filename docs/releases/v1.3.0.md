# Buildmesh v1.3.0

<!-- Audience: Buildmesh users. Lifecycle: draft before the matching tag is published; historical release record afterward. -->

_2026-09-20 — 50 commits since v1.2.0 (2026-08-21)_

v1.3.0 is a **breadth** release. The Inspector harness table is now generated from the Rust catalog so the front- and back-ends cannot drift, **Cline** joins the Spawn Menu as a Native Provider, **Meta Muse** lands as a first-class Windows harness, the Issues/PRs probe grows a full-width body plus a per-row merge-strategy picker, and the Usage tab learns to remember the last reading each provider reported so a start-of-day launch no longer blanks Antigravity, Grok, or Muse. Saved Spawn Configurations, the Pilot-light → Circuit shortcut, and the editable per-circuit step slots are the workflow features that earn their place in the unobtrusive corners of the app.

---

## Highlights

### Harness capability catalog generated from Rust (#1803)

The Inspector's per-harness capability data used to live in a hand-typed TypeScript table (`harnessCapabilities.ts`, ~510 lines) that mirrored the Rust adapters and could silently drift. v1.3.0 collapses the duplication: the Rust harness catalog emits a generated `HarnessCapabilitiesTable` JSON + TS pair into `src/types/generated/` during `cargo test` (the same `TS_RS_EXPORT_DIR` gate as `ts-rs`), so the Inspector table is the canonical Rust output. A drift-pin Vitest guard reads the generated JSON and fails if either copy moves without the other. The `claude` profile id is mapped to the `anthropic` adapter explicitly so the capability row survives.

### Cline is a supported harness (#1783)

When `cline` is installed (the npm install on Windows, or `cline` on PATH on macOS/Linux), a **Cline** row appears in the Spawn Menu and can be launched with prefill, model override, and reasoning effort (`none|low|medium|high|xhigh`) — the closed vocabulary the CLI itself accepts. Sessions resume with `cline -i --id <id>`. Cline is a **Native Provider**: it owns its own `cline auth` flow, so Buildmesh never writes Cline's configuration. When you attach one of your Model Provider accounts to a `cline:` spawn, Buildmesh resolves a surface-level fallback — any Anthropic- or OpenAI-surface pairing for the same account will do, so existing Claude Code / Codex credentials work without a separate Cline sign-in. Detection walks PATH, `~/.cline`, `CLINE_BIN_PATH`, and the npm shim; WSL is not a supported runtime for Cline in this release.

### Meta Muse on Windows (#1767, #1782, #1789)

Muse Code 1.3.0+ ships a native Windows binary that accepts the same flags as the Linux/macOS builds. Buildmesh now surfaces it in the Spawn Menu alongside the WSL fallback row. With both installs present, the Windows-native entry wins (no `WSL: …` suffix) and the WSL row hides; WSL-only users keep the existing `Meta Muse (WSL: Ubuntu)` row. Three follow-ups ship with the same feature:

- **#1782 — AI-context links repaired for native launches.** On Windows checkouts where Git stored the `AGENTS.md` / `.agents/skills` links as plain pointer files, Muse was hard-failing on launch. The repair preflight now runs for both native and WSL runtimes, with a manual-CLI workaround documented in Troubleshooting.
- **#1789 — `--disable-sandbox` baked into the spawn recipe.** Muse runs its sessions inside its own always-on OS sandbox, which denies access to the system credential store. `git` and `gh` from inside a Muse node were getting 401s on every push while sibling harnesses worked — Buildmesh now disables Muse's sandbox at spawn (matching every other agent) without touching `--disable-approval` or workspace trust.

### MiniMax Code attention-hook plumbing (#1805)

MiniMax Code 0.4.12+ exposes an Agent-Plugin hook surface (`hooks/hooks.json` + per-event scripts; stdin JSON carries `hook_event_name`, `session_id`, `transcript_path`). v1.3.0 ships the Buildmesh `io.buildmesh.attention` plugin install path: a `provision_attention_hooks` adapter method merges a Buildmesh `Stop` + `PermissionRequest` entry into the user's `<mcode-data-dir>/plugins/io.buildmesh.attention/hooks/hooks.json`, idempotent and additive (sibling user-authored handlers and unrelated events round-trip untouched), and malformed existing files fail closed. Stdin-delivery reaches a real localhost listener in the unit test.

**Status: dormant in this release.** The wiring is locked in but `requires_attention_hook` stays `false` per the issue #1796 acceptance line — the spawn-time gate at `agent::spawn::provision` does **not** call the seam yet. The follow-up that validates the callback reaches the Node Digest over a live mcode TUI only has to flip the descriptor and re-check the seam. Users do **not** see the plugin on disk in v1.3.0.

### Saved Spawn Configurations (#1759)

You can now save the model, reasoning effort, prefill prompt, and harness for a spawn under a name, then launch it later from the Spawn Menu without re-entering anything. Configurations are stored in the new `spawn_configurations` preferences module and ride the same seam as manual spawns, so the same Spawn Recipe applies (no double-config). A **Spawn Configurations** submenu appears in the Spawn picker once at least one is saved.

### Issues and PRs probe overhaul (#1786, #1806)

The probe rows are rebuilt around three ideas: text first, badges second, action buttons third.

- Each row's body region now spans the **full row width** beneath the title + action columns (clamped preview and expanded panel), so long Issues/PR text is no longer squeezed beside the buttons.
- A **toolbar search** in Issues and Pull Requests matches on title, body, and labels (issues) or head ref (PRs) as you type.
- Quiet **metadata badges** sit under each title: label chips (with `+N more`), branch chip, fork chip (only when it differs from your repo), draft chip, and a coloured left-edge **status stripe** for blocked/draft/unknown mergeability.
- The row's blocked-by warning is now an amber chip + stripe instead of inline text.
- A row with an empty body no longer shows an expand chevron.
- A **contributor pill** next to the labels/branch links to the author's GitHub profile (open/fail-open — never a dead link).
- **Merging a pull request** opens a strategy picker: **Squash and merge** (default), **Create a merge commit**, or **Rebase and merge**. The confirm button names the strategy you picked and the branch is deleted afterwards as before. Merge stays a two-step action.
- The **ready-for-agent** tag toggle on an issue row no longer repeats its `+` / `✓` marker twice — the icon is the sole affordance.

### Mesh probes from the palette (#1754)

The omnibar now indexes one **Open \<Destination\> in \<Mesh\>** entry per mesh-lens probe tab × mesh pair — for example, "Open GitHub Issues in ProjectY". Selecting it clears the target tab's stale context pin, selects the mesh, and opens the probe tab in that scope. Host-lens (Usage) and Agent-lens (Agent Changes) tabs are not eligible (Usage is app-wide; Changes needs a focused node).

## Providers & harnesses

- **Cline** — first-class, Native Provider. See **Highlights** above.
- **Meta Muse (native Windows)** — see **Highlights** above.
- **MiniMax Code transcripts** (#1799, #1733) — `messages.jsonl` history hydrates the Coordinator digest; archived sessions appear in the resume picker. The Muse session-log watcher feeds the attention turn signal in the same shape.
- **Cursor Enterprise billing-cycle spend** (#1739) — replaced the legacy `GET /auth/usage` request-limit probe with Cursor's current Dashboard flow (`GetPlanInfo` + `GetCurrentPeriodUsage` + aggregated events). Individual and pooled limits stay distinct, uncapped spend reads as **No individual limit**, and `0` is a valid reading rather than a missing wire field.
- **Command Code monthly allowance** (#1731) — the **Command Code** row in the Usage tab now reports the account's monthly allowance alongside current spend.
- **Piloted Autopilot now opens its Circuit run** (#1763) — the Pilot light in an Agent Node's title bar is a button when it's backed by Circuit ownership, opening the run in the Circuits Probe (the same path the kebab menu's circuit row uses). A legacy Autopilot run or a cancelled/archived Circuit stays static. The duplicated "Autopilot failed / Agent failed" chip on the card header is removed — the error-toned Pilot light carries the failure alone.

## Circuits

- **Continue a failed review, keep approvals waiting** (#1740) — a Circuit run that errors mid-review no longer drops the worker or strands the reviewer's queued approvals. The continuation seam reruns the failed step with the same inputs and surfaces a non-fatal **Review was continued** badge in the diagnostics, with the underlying failure still in the audit trail.
- **Per-circuit step slots are editable in the blueprint editor** (#1736) — the "all N of this circuit's step slots are busy" copy used to report `autopilot_circuits.concurrency_limit` with no way to change it. A **Step slots** select now lives in the circuit editor header; the underlying change is a `set_autopilot_circuit_concurrency_limit_inner` accessor with a markerless-legacy review-graph classifier that mirrors the canvas parser.
- **Recovered review source handoffs** (#1755) — reviews that completed under the old code path now resolve their source handoff correctly on resume.
- **Watchdog recovery waits for quiet turn readiness** (#1728) — the watchdog no longer snaps in mid-thought; recovery only fires once the worker signals a clean handoff.
- **Inspector capability table** (#1803) — see **Highlights**.

## Usage meters

- **Last-known fallback** (#1804) — Antigravity, Grok, and Muse only report usage while their harness login is fresh. Buildmesh now remembers the last reading each provider reported for up to seven days and shows it, labelled **Last known value · N days ago**, so a stale figure is never mistaken for a live one. The remembered store is keyed by provider id, lives at `usage_last_known.json` in the app data dir, survives restarts, and reads as empty on a missing or corrupt file. Live rate-limit and transport errors and a rejected-but-configured API key keep their existing treatment — only `Outcome::keep() == drop` falls back. With nothing remembered, the meter stays hidden as before. See **ADR-0037**.
- **Outcome seam hardening** (#1745, #1790) — the UsageAdapter failure reason is now stated once at the seam. Eight adapter migrations off the legacy shim ship in the same slice.

## UI

- **Native Windows 11 caption buttons** (#1764) — minimise / maximise / close now show the Snap Layouts flyout on hover over **Maximise**, the standard hover and pressed backplates, and the dim glyphs for an unfocused window. The title bar itself is unchanged.
- **Native macOS traffic lights** (#1765) — red/yellow/green now reveal all three glyphs at once on cluster hover (not on per-button hover), darken while held, and turn flat grey with no glyphs when the window is unfocused — going back to colour as the pointer approaches so you can see what you are about to click. Drawn at the standard macOS size; the green button still maximises rather than entering full screen.
- **Picker submenus stay open on diagonal cursor paths** (#1801) — moving the cursor diagonally into a submenu no longer closes the parent menu.
- **Single-caret hover contract** in harness dropdowns (#1735) — only one menu caret reveals its children at a time.
- **Sidebar mesh sync is failure-only** (#1727) — the sidebar mesh-sync indicator stays quiet on success and only paints itself when something went wrong. A force-sync menu item restores the on-demand action.

## Reliability

- **Agent spawn lifecycle surfaces failures** (#1787) — the **Start review or circuit** button on an Agent Node now follows the same liveness check the backend already uses (`PROCESS_REGISTRY.is_alive`) instead of the node's `pending`/`spawning` status alone. A node whose PTY reader is actually registered but whose DB row is still transient — or stranded on "Starting…" by an upstream swallow — lights up as eligible immediately, so you can kick off a review without waiting for the status badge to flip.
- **Detached-spawn wrapper** — a class of node-spawn failures that used to leave an Agent Node stuck on "Starting…" until app restart — every `SpawnOutcome::Skipped` short circuit, `SpawnOutcome::AlreadyActive`, and any panic that escaped the spawn future — now flows through the session lifecycle and emits a terminal `node-spawn-failed` (or `node-spawn-completed`) event. The badge updates to **Error** (or **Running**) instead of lying indefinitely.
- **Command Code typing on Windows** (#1785) — Command Code 1.56+ (Ink 7) can ignore TUI keys until Ctrl+C if a paste or startup keyboard probe leaves the prompt stuck. v1.3.0 skips the kitty-keyboard probe, does not wrap Command Code pastes in bracketed-paste sequences, and gives every agent PTY a colour-capable `TERM` so the workaround does not leave the TUI unstyled. New nodes skip the probe by default; see Troubleshooting if an older node is still stuck.
- **Windows terminal cursor frame ordering** (#1795) — fixed the text caret jumping around during animated Codex redraws (including Astra's composer glitter). Buildmesh now bundles a matching Microsoft ConPTY runtime pair that preserves synchronized frame ordering. Animations remain enabled; restart Buildmesh after upgrading to use the new runtime.
- **Pilot-light click seal** (#1763 follow-up) — failure chips stay reachable on a multi-member Agent Node header that draws the focused member's Pilot light only; an unpiloted node or cancelled/terminal Circuit draws no light at all so its errors are not hidden behind a missing affordance.

## Infrastructure

- **Harness capability catalog generated from Rust** (#1803) — see **Highlights**.
- **Enforced ESLint + React Hooks gate** (#1741) — flat ESLint 9 config with `rules-of-hooks` as an error and `exhaustive-deps` as a warning pinned to `--max-warnings 0`. A `lint:fixtures` step runs ESLint against two intentional-violation fixtures and asserts each one trips its target rule, proving the React Hooks rules are live. Both run as part of `scripts\check.ps1` and the GitHub Actions quality job.
- **Resolved-harness IPC + provider facet** (#1656, #1743) — a new `preferences::resolver::cascade` owns the four-layer spawn-config cascade (explicit → mesh override → mesh legacy → application default → native) and an IPC `get_resolved_harness_view` returns the full per-harness cascade for the frontend's provider facet. Foundation work; subsequent phases land in v1.4.0.
- **Six `spawn()` entry points unified** (#1742) + **HTTP module divided into server + router + state** (#1724) — both internal seams that consolidate the spawn and HTTP code paths behind single owners. No user-visible behaviour change.
- **`spawn_agent_inner` typed end-to-end** (#1730) — the spawn-option id is now `SpawnOptionId { harness_id, provider_id }` instead of a stringly-typed pair.
- **circuits_tests migrated to per-test in-memory DBs** (#1691) — the parallel-safety fix removes a long-standing flake. `db::circuit_tests::_inner` / `_locked` helpers are now safe to run at default test threads.
- **devDependencies bump closes five GHSA advisories** (#1761) — npm audit + cargo audit both clean.
- **Harness capabilities matrix** (#1800) — a consolidated reference page lives at `docs/learning/harness-capabilities-matrix.md` and is the single source of truth for per-harness capability claims.
- **`muse.exe` available-on matrix widened** + **AI-context pointer-file repair** + **sandbox flag** — see **Highlights / Meta Muse on Windows**.

## Upgrade notes

- **Last-known usage cache is empty on upgrade** — the cache is a new file in the app data dir; nothing migrates from v1.2.0, so the meters behave as before (no stale fallback shown) until each provider reports at least once after the upgrade.
- **Window controls look different on first launch** — the Windows 11 caption affordances and macOS traffic-light set are visual upgrades, not behaviour changes. The Windows snap layout flyout only appears on hover over **Maximise**; macOS unfocused state shows flat grey lights with no glyphs.
- **Harness Capabilities table location** — the Inspector's per-harness data now lives in `src/types/generated/HarnessCapabilitiesTable.{ts,json}` (regenerated by `cargo test`). Hand-edits there are silently overwritten.
- **Cline WSL** — not a supported runtime in v1.3.0. Cline installs on Windows, macOS, and Linux are supported; WSL is intentionally excluded (the cross-runtime probes would otherwise carry behaviour that is undocumented and untested for this slice).
- **Muse sandbox is now disabled at spawn** — Muse no longer runs inside its own OS sandbox. The approval policy (`--disable-approval`) and workspace trust are unchanged; the `--yolo` flag remains rejected per the issue #1705 decision.
- **Auto-updater** — existing installs are offered v1.3.0 automatically. Update integrity is verified via the existing minisign key (unchanged from v1.2.0).
