# Buildmesh v1.1.0

_2026-08-20 — 50 commits since v1.0.0 (2026-07-17)_

v1.1.0 is a stabilisation and capability release. The biggest internal shift is a new **Harness Capability Contract** that makes spawn-config resolution type-safe and predictable across the whole app. Around that, the four shipped Codex/OpenAI/Kimi/MiniMax Code providers hardened their wiring, the in-app terminal got a major latency pass, and the in-app autopilot got a safety gate so it can no longer silently auto-start with an incompatible harness.

---

## Highlights

### Agent Harness Capability Contract (#1149 → #1157)

A new type-level capability mask guarantees every spawn knows exactly which model/effort fields it can set per harness. The old `if supports_model_override()` guard was silently forwarding `--effort high` to providers that ignore it — that path is now closed.

The resolver now runs as an explicit, testable cascade:

> **explicit** (Agent Node spawn argument) → **mesh override** → **mesh (legacy)** → **application default** → **native**

- **#1149 — Capability contract + spawn-config resolver** — `&ResolvedAgentConfig` is the seam; capabilities flow through `evaluate(input) → ResolvedAgentConfig`.
- **#1150 — Application-level defaults per Agent Harness** — sparse `harness_defaults` map on `AppPreferences`; new **Harness Defaults** section in App Settings, capability-gated.
- **#1151 — Per-Mesh harness overrides** — `meshes.harness_overrides` JSON column (schema v32 → v33); one-shot backfill; new `upsert_mesh_harness_override` / `remove_mesh_harness_override` / `clear_mesh_harness_overrides` Tauri commands; redesigned Mesh Properties panel.
- **#1155 — Cascade layer 1 (explicit Agent Node spawn argument)** — `SpawnRequest::explicit` plumbed end-to-end at every spawn call site.
- **#1157 — SpawnRequest::new() constructor + `resolve_spawn_config` seam** — pure resolver extracted from `spawn_agent_inner` so the cascade is end-to-end testable.

### Autopilot compatibility gate (#1152)

AutoAutopilot can no longer start with an incompatible default harness. A new pure `evaluate(input) → {allowed, reasons[], resolved_harness_id, …}` in `autopilot/compatibility.rs` rejects:

- `NoResolvedHarness`
- `UnknownHarness { harness_id }`
- `PlainTerminal`
- `MissingPrefill { harness_id }`
- `MissingAttentionHook { harness_id }`
- `WorktreeDisabled`

The probe UI shows a banner, disables the master checkbox, and disables **Looping Start** (Stop stays available). `update_mesh_autopilot` / `set_mesh_autopilot_enabled` reject `enabled=true && !allowed` at the API layer; the scheduler revalidates at the top of `poll_mesh`.

### Terminal latency pass (#1122)

Progressive text entry latency got a coordinated three-part fix:

1. **`@xterm/addon-webgl`** renderer with DOM fallback (`loadWebglRenderer.ts`).
2. **Split `write_to_agent`** into a fast PTY-write path (async runtime) and a slow DB-only signal path (`spawn_blocking` only for newline-bearing writes).
3. **ASCII-only fast-path** in `TerminalWriter` to bypass `requestAnimationFrame` + xterm's internal rAF stacking.

#1134 removed a stale fast-path helper caught by the new tests.

### Spawn pipeline collapse (#1140, #1152)

- **`SpawnIntent` seam** — every spawn now flows through a single intent type, regardless of trigger (manual, autopilot, probe, warm-claim).
- **`SpawnContext` recovery + post-success ownership** — closes a data-loss path when the spawn succeeds but downstream ownership handoff fails.
- **`agent::process` deepened** — provider_menu split into its own module; `provider_menu::list_providers` is now the single source of provider order (the App Settings harness list, the New Agent dialog, and the mobile ProviderPicker all read from it).
- **`agentNodeStore` split** — listeners extracted to typed `agentNodeListeners.ts`; `withOptimistic<TPatch, TResult>` helper de-duplicates three inline optimistic-update + rollback patterns.

### Database schema evolution (#249)

Single `evolve_to` runner replaces the per-version migration ladder. Future schema bumps drop into one place and run deterministically with version-aware logging.

## Providers

### MiniMax Code CLI (`mcode`) — native harness (#1140, #1129)

- Native integration as a First-class Model Provider.
- Prefill + model override args corrected (#1129) — `--model` was being clobbered by the harness wrapper.

### Kimi Moonshot — restored as First-class Model (#fd886ec, #65583d0)

Kimi was previously collapsed into a dual-id hybrid that broke credential lookups. v1.1.0 restores it as a standalone First-class Model Provider and unifies the identifier (no more dual-id surprise).

### OpenAI & Codex usage meters (#1116, #1117)

- **Codex** — WSL credential discovery + `/wham/usage` schema reverse-engineered; CLI re-auth remediation surfaced in the UI.
- **OpenAI** — keyed provider row + two-round-trip Admin/Project key probe.
- See **ADR-0026** for the schema + threat model.

### Codex resume reliability + terminal parity (#1097)

- Resume path hardened — sessions that previously fell off the spawn path now recover correctly.
- Terminal byte parity fixed — what you see in the in-app terminal matches the native CLI output.
- Proxied routing hardened (#1098) — account swap during a session no longer leaks the previous account's env.

### OpenCode Console fixes (3 issues)

- **Account restore on mount, persist-on-switch, live usage** (#c7f6ac8) — switching away and back no longer drops your account.
- **Workspace parsers match the live Console wire shape** (#9cfc76e) — multi-root workspaces now parse correctly.
- **Wire-shape + URL-prepend + first-time sign-in** (#0329361) — first-run sign-in flow stops failing on URL prepending.

### Provider-settings credentials vs pairing endpoints (#f4eb94b)

**ADR-0025** refactor — the provider-settings dialog now distinguishes between credential endpoints (API key, OAuth token) and pairing endpoints (device-flow pairing). No more "which secret does this field need?" confusion.

### Provider brand registry consolidated (#1055)

`ProviderIcon` brand registry is now the single source of truth for provider glyphs. The mobile ProviderPicker fallback glyph (#e018857, #166cf49) and the desktop ProviderIcon both read from the same module.

## Reliability

- **User-driven recovery for Suspended Agent Nodes** (#1121) — closes the OpenCode clean-exit orphan data-loss path. If a node ends up Suspended, you can now resume it from the UI instead of restarting from scratch.
- **Mobile expired-session recovery** (#1120) — data screens no longer 500 when the session token has expired; they prompt to re-auth.
- **Warm-claim spawn persists pool slug to `worktree_name`** (#1059) — pool-based worktree claiming now remembers the slug across restarts.
- **Probe `activePath` resolves to worktree dir** (#1059) — when an agent node is inside a worktree, the probe uses the worktree path, not the main checkout.
- **Thread-local tracing capture** (#1138) — fixes #1007 flake; per-thread isolation is now guaranteed by the type system.
- **Test merge-button timeout extended** (#370e283) — absorbs CI cold-start latency so the suite doesn't red on first run.
- **Reducer test timestamps pinned** (#1101) — reducer tests no longer drift with wall-clock time.

## Infrastructure

- **9 security advisories closed** (#1161) — npm audit + cargo audit both clean (lockfile-only updates, zero code churn).
- **vitest unit suite in quality job** (#1114) — the quality gate now runs JS unit tests alongside cargo, closing the gap where JS regressions could merge on a green Rust build.
- **Cross-platform build checks streamlined** (#1088) — release-blocking checks run on every PR; informational checks run on a schedule.
- **Generated session status type** (#1105) — TypeScript session status is now derived from the Rust `enum SessionStatus` via `ts-rs`. No more hand-mirrored union drift.

## Upgrade notes

- **Database schema** — `meshes.harness_overrides` is a new JSON column. The one-shot `mesh_harness_overrides_migrated_v33` backfill runs on first launch and is idempotent.
- **App Settings** — the **Harness Defaults** section is new and capability-gated per provider. Setting a default for a provider that doesn't support it is rejected at the API.
- **Mesh Properties** — the harness overrides UI replaces the legacy single-harness dropdown with a sparse override list. Existing meshes keep their current settings via the legacy slot in the cascade.
- **Auto-updater** — existing installs will be offered v1.1.0 automatically. Update integrity is verified via the existing minisign key (unchanged from v1.0.0).
