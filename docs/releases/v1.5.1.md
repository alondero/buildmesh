# Buildmesh v1.5.1

<!-- Audience: Buildmesh users. Lifecycle: draft before the matching tag is published; historical release record afterward. -->

_2026-10-19 — 1 commit since v1.5.0 (2026-10-18)_

v1.5.1 is a **fix** release for macOS and Linux. Agents launched from a GUI (Finder, the Dock, a desktop launcher) now start with the runtime they were installed with on PATH, so an NVM-installed agent no longer fails to launch because its Node runtime could not be found. Windows behaviour is unchanged.

---

## Highlights

- **GUI launches on macOS and Linux find the agent's own runtime.** When Buildmesh starts an agent from Finder or the Dock, it can inherit a minimal PATH. Discovery could still find an NVM-installed agent by its absolute path, but the agent's `#!/usr/bin/env node` entrypoint then had no way to find the Node runtime sitting next to it, and the launch failed.
- **The fix prepends the agent's own directory to the child PATH.** For native Unix terminal and background agent launches, Buildmesh now puts the resolved executable's directory at the front of the child's PATH, so the agent uses the Node version that owns its install. Your inherited PATH entries still follow it, and Buildmesh's own environment is unchanged.
- **Nothing else moves.** Bare command names and relative executable paths keep the inherited PATH, and Windows launches — and launches that cross between Windows and a Linux runtime — keep their existing environment handling exactly as before.

---

## Upgrade notes

- **No action needed.** The fix is applied to the agent's child environment at launch; there is no setting to change and nothing to reinstall.
- **Windows is unchanged.** The in-app auto-updater offers v1.5.1 to existing Windows installs as usual, and the Windows installers and signed Android APK ship as they did in v1.5.0.
- **macOS is still early access.** The macOS builds remain ad-hoc signed with no Developer ID certificate and no notarization, so Gatekeeper blocks the first launch exactly as SmartScreen does on Windows — right-click the app, choose **Open**, then **Open** again. The fix above is included in the macOS build, but it was verified on Linux rather than on native Apple Silicon or Intel hardware; the `MACOS-INSTALLED-RECEIPT.json` attached to this release records that coverage.
- **The APK stays out of the updater feed.** `latest.json` carries the Windows and macOS desktop platforms only; the APK keeps its own `.sha256` sidecar.
