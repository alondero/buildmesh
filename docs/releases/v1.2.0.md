# Buildmesh v1.2.0

_2026-08-21 — 50 commits since v1.1.0 (2026-08-20)_

v1.2.0 is a **deepening** release. The Harness Capability Contract introduced in v1.1.0 gets hardened end-to-end: capability descriptor and launch recipe are now owned by the same adapter method, the Autopilot Agent Node launch seam has a single owner across Issue and Loop modes, and the GitHub prefill prompt has one authoritative formatter. Around that, two new providers land (Cursor CLI and DeepSeek), and the Agent Changes probe stops both flooding the backend and pinning `run_blocking` threads when superseded.

---

## Highlights

### Harness capability coherence (#1179, #1186)

The v1.1.0 capability contract shipped descriptor and recipe from independent code paths. v1.2.0 collapses them into one coherent `PreparedHarnessLaunch` contribution emitted by `AgentProvider::prepare_launch`, so a single table-driven test (`capability_recipe_coherence`) proves they cannot disagree.

- **#1179 — Capability descriptor and launch recipe are now one adapter method.** New `agent::launch` module owns `HarnessLaunchInput`, `SessionIdModeRef`, `PreparedHarnessLaunch`, `HarnessEnvironmentPolicy`, and `default_prepare`. The `AgentProvider` trait gains `capabilities()` (default composes the existing flag methods), `effort_control()` (Anthropic + Codex each override with their actual vocabulary), and `prepare_launch()` (default delegates to `default_prepare`). `build_spawn_command_prepared` shrinks from 187 to 50 lines; WSLENV bookkeeping extracted to `apply_routing_env`, `apply_codex_proxy_credential`, and `append_to_wslenv` (dedupe-by-base-name — the rule the two previous inline blocks had duplicated).
- **mcode product decision (recorded in adapter doc-comment).** MiniMax Code's `--model <provider>/<model>` only exists on the `exec` subcommand; Buildmesh launches the interactive TUI, which rejects it. Code-defined decision: **keep TUI; drop the `supports_model_override` claim.** `supports_model_override()` flipped to `false`; `model_args` + `normalize_mcode_model` deleted; `mcode_interactive_recipe_never_carries_model_arg` regression-pins the contract. A future `mcode exec`-based launch mode would re-advertise the flag once its lifecycle work lands.
- **#1186 — Grok/Kimi capability drift resolved.** `CONTEXT.md:10` listed Grok Code and Kimi Code as Default-Only Harnesses that ignore Buildmesh model overrides, but their adapters reported `supports_model_override() = true` and emitted `--model`/`-m`. Probes proved both binaries DO accept the flag (Grok responded with "unknown model id" — proving it tried to set; Kimi responded with "Model 'kimi-k2' is not configured in config.toml" — proving it parsed). The historical decision (#913 / wayfinder map #908) was based on assumption, not probe. The adapter code was right; the doc was stale. New positive regression pins: `grok_interactive_recipe_carries_long_model_arg` + `kimi_interactive_recipe_carries_short_m_model_arg` (mirror mcode's negative pin).

### Autopilot launch seam (#1178)

`spawn_autopilot_node` and `spawn_loop_node` duplicated the same 7-step orchestration (row create → lifecycle `Pending` → ledger row → evaluator register → `node-created` emit → background stage-2 → watcher arm). v1.2.0 extracts both into one crate-private function: `crate::autopilot::node_launch::launch_autopilot_node`.

- The new `AutopilotNodeLaunchPlan` carries policy facts only (`mesh`, `provider`, `branch`, `initial_name`, `intent`, `run`, `worktree_policy`, `watcher_issue_number`); the launch module owns the ordering and derives the watcher's prefill from `intent.initial_prompt()`.
- The loop runs return `Result<(), String>` to match the legacy contract — no caller changes.
- 8 new tests pin the pure helpers and the 3 ordering invariants (ledger precedes stage-2, `Pending` precedes ledger, evaluator register precedes watcher arm) via `include_str!`.

### Spawn prompt unification (#1180)

GitHub prompt formatting was duplicated across 4 modules (`commands/agent.rs`, `services/autopilot.rs`, `autopilot/launch.rs`, `agent/spawn.rs`). v1.2.0 collapses all three free functions into one seam: `SpawnIntent::initial_prompt()` returning an `InitialPrompt` newtype.

- **Truth table** pinned in `intent::tests`:
  - Issue w/ title → `Please work on GitHub issue #N — Title\n<url>`
  - Issue blank title → `Please work on GitHub issue #N\n<url>`
  - PR w/ title → `Please review pull request #N — Title\n<url>`
  - PR blank title → `Please review pull request #N\n<url>`
  - Handover → selected text verbatim
  - Loop → configured prompt verbatim
  - Fresh/Resume → `None`
- `create_pr_node_impl` now returns `Result<(IssueNodeDraft, SpawnIntent), String>` so the wrapper uses the SAME intent for `spawn_with_intent` — desktop draft and background launch can't drift.
- No new Tauri commands / HTTP fields / DB columns / TS types. `IssueNodeDraft.prefill: String` unchanged. Backward-compatible.

### Agent Changes probe performance (slices of #1165, #1181)

The Agent Changes probe was refreshing on every `GIT_CHANGED` event (~2 emits/s during an agent's edit burst) and pinning `run_blocking` threads on superseded walks. v1.2.0 fixes both halves.

- **#1165 slice 1 — frontend throttle.** `subscribeGitPathInvalidation(path, cb, options?)` now accepts `{ minRefetchIntervalMs?: number }`. Per-subscriber state hangs off a module-level `WeakMap` keyed by the subscriber object. `AgentReviewPanel` + `CenterDiffOverlay` opted into `minRefetchIntervalMs: 2_000` (matches `useGitSummary`; longer than the backend coalescer's 500 ms). A burst of 5 events in 500 ms collapses to one trailing refetch instead of one per event.
- **#1181 slice 2 — Rust-side cancellation.** `diff_node_against_base` now cancels stale work via a module-level `Lazy<Mutex<HashMap<i64, Arc<AtomicBool>>>>` keyed by `node_id`. The cancel flag is polled at two granularities (top of each delta loop, before each `build_hunk` call — the costliest step). `DIFF_CANCELLED` sentinel returned to the frontend so its `.catch` can identify "aborted, not a real failure." A new `AbortController` in `useRef` on both panels drops stale local results so the UI doesn't flicker between superseded refetches.

## Providers

### Cursor CLI (`cursor`) — three-step onboarding (#1175, #1173, #1177)

Cursor's interactive coding agent is now a first-class harness with full wire-up.

- **#1175 — Harness adapter.** New `Provider::Cursor` variant, `CursorAdapter` impl, `cursor-agent` (and bare `agent`) binary detection, `--resume <id>` for archived sessions, `--model` override, positional prefill, official brand assets (`#1B1913` chip + cube mark). Cross-platform spawn: `cmd.exe` on Windows (the installer exposes a `.cmd` shim), direct on macOS/Linux.
- **#1173 — Usage meter probe.** Cursor's coordinator-side balance endpoint integrated with the existing `FETCHABLE` + `cached_or_fetch` dispatch and the `ProviderUsage` union.
- **#1177 — Transcript discovery.** Cursor's workspace-scoped JSONL transcripts now discoverable via the shared reader + archive discovery (the `~/.cursor/projects/` layout). `produces_readable_transcript()` flipped to `true` once the wiring landed.

### DeepSeek Harness / First-Class Model Provider (#1127)

DeepSeek is promoted from a true Generic to a First-class Model Provider. Wired into all five first-class keyed-provider seams in lockstep: `BUILTIN_PROVIDER_ACCOUNTS`, `first_class_surfaces`, `deepseek_default_tiers()`, `deepseek_api_key_resolved()`, and `FETCHABLE` + `cached_or_fetch` dispatch.

- **Surfaces published:**
  - Anthropic-compatible: `https://api.deepseek.com/anthropic` — `deepseek-reasoner` for Opus/Fable/default, `deepseek-chat` for fast tiers.
  - OpenAI-compatible: `https://api.deepseek.com/v1` — `deepseek-chat` default (Codex single-model contract).
- **Usage probe** follows the `kimi_usage` / `openrouter_usage` balance pattern: `GET https://api.deepseek.com/user/balance` with Bearer auth. `total_balance` is a **decimal string** per issue #1125 contract — parsed via `f64::from_str` after trim.
- **Status mapping:** 401/403 → `logged_out("Invalid API key")`, 429 → `unavailable("Rate limited")`, 200 → `ProviderUsage` with `balance: Some(BillingBalance)`.
- **Brand registry** primary id is `deepseek` (with `dsh` and `deepseek-harness` as aliases) so `brandFor('deepseek')` resolves to its own brand record rather than aliasing.

## Upgrade notes

- **`Provider::Cursor` is a new enum variant.** Any persisted `Provider` strings deserialize unchanged (`"codex"`, `"agy"`, etc. are stable); the new `"cursor"` is additive. Persisted `spawn_option` composite ids continue to use the existing v19 migration table.
- **DeepSeek promotion from Generic to First-class Model.** Existing DeepSeek custom accounts (configured as a Generic with a custom endpoint) lose the "custom endpoint" surface and gain the two built-in surfaces (Anthropic-compatible + OpenAI-compatible). Re-save the account in Settings → Providers to migrate.
- **No schema bump.** `meshes.harness_overrides` (v33) is unchanged.
- **Auto-updater** — existing installs will be offered v1.2.0 automatically. Update integrity is verified via the existing minisign key (unchanged from v1.0.0 / v1.1.0).
