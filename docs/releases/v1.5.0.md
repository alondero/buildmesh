# Buildmesh v1.5.0

<!-- Audience: Buildmesh users. Lifecycle: draft before the matching tag is published; historical release record afterward. -->

_2026-10-18 — 103 commits since v1.4.1 (2026-10-13)_

v1.5.0 is a **circuit visibility, phone parity, and first-macOS-build** release. A Circuit Run now has an **Overview** tab on the node card that names the run, shows its step rail in flow order, and lets you move a genuinely stuck step on by hand — recorded in history as your decision, never as an approval. The Attention sidebar splits into counted **Failed sessions**, **Needs input**, and **Paused sessions**, and each card shows the actual question or permission the agent is waiting on. Both phone clients can now see Circuit Runs and reviews and act on the steps waiting on you, and macOS builds appear on the release for the first time.

---

## Highlights

### See a Circuit Run, and unstick a step yourself (#2376)

A node card whose agents belong to a Circuit Run now leads its activity tabs with an **Overview** tab, for live and finished runs alike. It never selects itself — your terminal stays until you choose it — and a `!` badge marks a run that actually needs a person: an approval, an Unverified checkpoint, or an unacknowledged recoverable failure. Merely waiting does not raise the badge.

The header names the circuit, its state or review verdict, the review round, elapsed time, and the run id, with **Pause**, **Resume** and **Cancel** while the run is live. A step rail lists the run's graph in flow order, marked done, current, failed, remaining or skipped; each row expands to its times, verdict, review report, agent link and error.

You can also **move a stuck step on by hand** when Autopilot is waiting on stale background work or on an input that was already answered. Buildmesh refuses the push for review verdicts, conflicted evidence, and paused or finished runs, and a manual push is recorded in Run History as "Moved on by an operator" — it grants no review approval and never fabricates one.

The phone clients and the Probe's run card do not offer the manual push yet, and a **Review Verdict** step held by stale background work still has no way out.

### Attention sessions are grouped, and show what they are asking for (#2427)

The Attention sidebar no longer presents one flat list. Sessions are split into three counted groups — **Failed sessions**, **Needs input**, and **Paused sessions** — and each card now shows the actual question or permission request the agent is waiting on, instead of only a status. Each session has one clearly labelled **Open terminal** action rather than two ways to reach it; failed sessions still offer **Retry**, and paused sessions offer **Resume** whenever a saved session identity exists. See [Find agents that need attention](../user-guide.md#find-agents-that-need-attention).

### Clone a launch configuration instead of retyping it (#2419)

Every saved recipe in a harness's launch-configurations submenu now has a **Clone** button beside **Edit**. Clone opens the same editor pre-filled from the row you clicked — harness, provider, model, effort, extra args — with a "copy" suffix on the name, so changing one field, such as a model version or an effort level, leaves the original untouched. An unsaved clone has no Delete until you save it, and Cancel returns you to the row. The same **Clone** action is available in Settings → Launch Configurations. See [Launch Configurations](../user-guide.md#launch-configurations).

### Restore a review agent you thought you lost (#2353)

In Activity and History, expanding a run and choosing **Open** beside a step's agent now works even when that agent is no longer in your workspace: Buildmesh restores it from Agent History and focuses its canvas. A failed restoration reports the error and offers a retry, duplicate clicks are ignored, and a restored agent opens suspended so you resume its saved session to interact with it. See [Understand a circuit checkpoint](../user-guide.md#understand-a-circuit-checkpoint).

### Worktrees live in `.worktrees` (#2337)

New nodes and the pre-spawn warm pool now create worktrees at `<mesh>/.worktrees/<name>` instead of `<mesh>/.claude/worktrees/<name>`, so the container is no longer named after one tool.

**Your existing checkouts are not moved.** Nodes keep their saved paths, older `.claude/worktrees` checkouts still resolve, and archive discovery finds both layouts. To keep the old location for new nodes, set `.claude/worktrees` in Settings → General → Worktree directory, or override per mesh in Project Settings → Worktree strategy. The AI-context portability action adds `.worktrees/` to your `.gitignore`, appending only the missing rule if your repo already has an older portability block. See [Worktrees, branches, and review](../user-guide.md#worktrees-branches-and-review).

### Your phone can see and act on Circuit Runs (#2435, #2356)

Both phone clients — the native Android app and the mobile web app — now show the active Circuit Run, its review round and verdict, and the decisions waiting on you.

From a node screen you can start the built-in Review Blueprint or an eligible saved review-derived circuit, and approve, record checkpoint outcomes, recover an eligible failed run, or cancel. Where a step is waiting on you, the node card carries an amber status line and a Circuit Run panel with confirmations. Approval, checkpoint, recovery and cancellation all go through the desktop's own eligibility checks, so an action that cannot work is refused rather than silently ignored, and a failed circuit read leaves the node list working instead of taking it offline. The web client also gains circuit attention filtering, live event refresh, and direct navigation to reviewer helper terminals. "Needs input" is still answered in the terminal.

### Spawn, review changes, and merge from the phone (#2386, #2336, #2373, #2443)

- **Spawn from anywhere.** Android carries the desktop's split spawn button on mesh cards, issue cards and pull requests: the main half starts with the mesh default, and the chevron offers prompt-capable options including your saved launch configurations. Starting from an issue opens the new agent directly — the old confirm dialog is gone — and starting from a pull request launches on the PR head with the same review prompt the desktop renders. Capture gained a **Mesh default** choice. If you choose something that cannot take a prompt, such as **Terminal**, it is kept and explained rather than silently swapped for another harness, with Start disabled until you clear the prompt or change the choice.
- **Review changes.** Both phone clients resolve a node's current Git branch, show its open pull request with checks, review decision and mergeability, and offer a confirmed squash merge with branch deletion. Merging stays disabled for drafts, unknown, conflicting, blocked or behind states, pending or failing checks, and required or changes-requested reviews. Both clients re-check mergeability immediately before sending the request, so a policy change mid-request stays authoritative on GitHub.
- **Overview leads to work.** Tapping a mesh name in Android **Overview** opens **Work** filtered to that mesh, clearing any stale search or attention filter. Each mesh header shows a status dot per open agent plus their count. A mesh with no open agents shows a muted name and path with **No agents yet**, while staying tappable.
- **Android Work matches the desktop sidebar.** Agents appear as compact mesh sections with the same status shapes and Circuit glyphs as the desktop, with one shared pairing bracket for agents linked by the same Circuit Run. Every agent inside a section is still individually tappable, and search or attention filters still keep the other members of a matching activity visible. A desktop that does not expose the relationship route simply shows standalone rows.

### macOS builds, ad-hoc signed (#2483)

Every tagged release now carries two native macOS builds — Apple Silicon (`aarch64`) and Intel (`x86_64`) — each publishing a `.dmg` installer, the versioned `.app.tar.gz` updater archive, a matching minisign `.sig`, and its own checksum manifest. The in-app updater feed now carries `darwin-aarch64` and `darwin-x86_64` beside `windows-x86_64`, and CI fails the release unless all three entries are present, signed, version-matched and resolvable.

The bundles are **ad-hoc signed**: genuinely signed and internally consistent, but with **no Developer ID certificate and no notarization**. Gatekeeper therefore still blocks the first launch exactly as SmartScreen does on Windows — right-click the app, choose **Open**, then **Open** again, or use System Settings → Privacy & Security → **Open Anyway**. No Apple Developer Program membership, certificate, Apple ID, team or API key is required, and distribution stays free.

The declared minimum macOS versions are 11.0 for Apple Silicon and 10.13 for Intel. These are bundle values read from each built `Info.plist`, **not** verified runtime minimums — see the upgrade notes.

## Fixes worth knowing about

**Circuit runs**

- A review now starts as soon as implementation finishes, instead of waiting for the run to idle (#2440).
- Historical stock runs accept manual review rounds (#2320).
- Run history names which run identity differs when a receipt is stale, so a recheck is not confused with a new attempt (#2447).
- Empty data and missing resources are distinguished from genuine persistence failures instead of reporting a save that never happened (#2446).
- A mesh snapshot now has request and mutation authority, and optimistic Agent Node commits and rollbacks are fenced against newer writes (#2394, #2393).
- The Stop hook no longer re-blocks a task whose phase is already complete (#2416), and the baked attention hook is fanned out to every running instance (#2433).
- A prompt a TUI dropped before it was reading is re-sent (#2358).

**Nodes, repositories and presence**

- Harness provenance is preserved from discovery through resume, so a resumed node is still the harness you launched (#2354).
- Node status is accurate for the six primary harnesses (#2351), and unavailable and stale repository status outcomes are preserved rather than overwritten by a newer refresh (#2389).
- Meshes that are not Git repositories are skipped and logged once instead of failing (#2355); Git roots resolve and scoped agent launches are preserved (#2307).
- An over-long auto-generated node name is shortened instead of refused (#2382), and Project Files opens for the mesh you actually right-clicked (#2482).
- **Project Files → Issues** no longer crashes, and Create PR and saved launch configurations are repaired (#2322). The Issues screen also gains issue triage, tags and launch choices (#2334).
- Long Codex handovers are delivered through files rather than truncated prompts (#2302).
- A slow launch or resume no longer moves you off the screen you opened (#2437), and a mesh row expands for the open mesh or agent (#2442).
- Spawn hover no longer strobes in narrow mesh rows (#2431).

**Interface**

- The Probe's Circuits tab no longer shows dangling headers or dead-end copy (#2479), and the Agent History tab has active-mode styling, a single Refresh toolbar, a populated repo select, and readable timestamps instead of raw nanoseconds (#2480).
- The canvas zoom controls and attribution badge follow the theme (#2481); the Theme label is no longer orphaned and the Sidebar views group is named (#2472).
- A new mesh opens focused on its folder picker (#2476), a mesh without a repository starts with worktrees off (#2441), and the export redaction copy no longer contradicts itself (#2474). AI context portability rows wrap cleanly at the 240px dock minimum (#2477).

**Security and privacy**

- `rustls` is updated, clearing four RustSec advisories (#2342).
- The test bridge is compiled out of production builds (#2341).
- Built-in defaults stay off the account write path (#2412).

## Performance

- Large, simple status deltas are delivered as a bulk patch instead of per-node writes, which is the most visible difference on a mesh with many agents (#2432).
- Unchanged text is borrowed rather than copied through redaction and the log writer (#2436), and eager output decoding and per-chunk allocations are removed (#2428).

## Upgrade notes

- **Worktrees move to `.worktrees` for new nodes only.** Nothing you already have is moved or re-pointed. If you rely on the `.claude/worktrees` path for new agents, set it explicitly in Settings → General → Worktree directory. See [Worktrees, branches, and review](../user-guide.md#worktrees-branches-and-review).
- **macOS is early access.** The DMGs are real, checksummed, ad-hoc signed builds, and this release has **not** been through an installed-app runtime check on real Apple Silicon or Intel hardware — no browser-quarantine test, no Gatekeeper approval record, no Finder launch, no authenticated CLI task, and no live updater install/rejection run on a Mac. Treat macOS as early access. The declared `LSMinimumSystemVersion` values (11.0 Apple Silicon, 10.13 Intel) are bundle metadata, not verified runtime minimums. Full detail is in the `MACOS-INSTALLED-RECEIPT.json` attached to this release.
- **Windows and Android are unchanged.** The in-app auto-updater offers v1.5.0 to existing Windows installs as usual, and the signed APK is published beside the installers as it was in v1.4.1.
- **The APK stays out of the updater feed.** `latest.json` carries the Windows and macOS desktop platforms only; the APK keeps its own `.sha256` sidecar.
- **Checksums.** `SHA256SUMS.txt` covers the Windows installers. Each macOS architecture has its own manifest — `SHA256SUMS-macos-aarch64.txt` and `SHA256SUMS-macos-x86_64.txt` — and the APK has its own `.sha256`.
